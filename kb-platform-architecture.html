System Overview — 4-Layer Architecture

How the UI, API, Plugin Engine, and MCP Tools compose into a complete Knowledge Base platform

ℹ
The AIDLC Knowledge Base platform is built across 4 separate repositories, each owning a distinct concern. The Plugin runs offline to build the KB artifact bundle (graph + cards + evidence). The MCP Tools load that bundle into Postgres + embed chunks via Bedrock. The API serves the data at runtime. The UI renders it.
Layer 1 · UI
Angular 18 SPA
D3 v7 · ngx-markdown · Axis UI · Okta
  • Knowledge Graph (D3 Layers + Explore)
  • Chat / KB Agent (SSE streaming)
  • KB Versions & Coverage dashboard
  • SDLC Workspace pipeline views
  • Traceability RTM graph
Layer 2 · API
FastAPI Backend
Python · LangGraph · NetworkX · psycopg3
  • Chat Q&A + SSE streaming (/fe/query)
  • Graph explorer (/re/graph/*)
  • SDLC artifact generation (/ws/*)
  • Bedrock Titan embedding (query-time)
  • Okta JWT auth + Entitlement middleware
Layer 3 · Plugin (OFFLINE)
KB Agent Engine
Python stdlib · Anthropic API · Claude Vision
  • 8-stage ingestion pipeline (PDF/DOCX/XLSX/Code/Email/Images)
  • LLM extraction → graph.json + cards.jsonl
  • Code lane parser (Java/TS/Python/SQL/COBOL)
  • G1–G10 integrity gates (re_anchor, check_kb, etc.)
  • NO embeddings — pure markdown file retrieval
Layer 4 · MCP Tools
FastMCP Server
Python · FastMCP · boto3 · psycopg3
  • 12 MCP tools (5 retrieval + 7 indexer)
  • kb_load: S3 → Postgres (7 tables)
  • kb_embed: Bedrock Titan v2 → pgvector
  • kb_promote: STAGING → ACTIVE
  • graph_neighbors: graph traversal proxy

Document Ingestion & Embedding Pipeline

From raw enterprise documents → chunked pgvector embeddings in Postgres

⚠
Two distinct phases: (A) The Plugin Engine builds structured KB artifacts from raw documents using Claude LLM — no embeddings at this stage. (B) The MCP Tools Server then loads those artifacts into Postgres and embeds text chunks using AWS Bedrock Titan v2.

🔑 Chunking & Embedding — Key Parameters

📐
Chunk Size: 512 words per chunk with 64-word sliding overlap. Pure word-count split (no sentence boundary detection).
🤖
Embedding Model: amazon.titan-embed-text-v2:0 via AWS Bedrock invoke_model. Dimension: 1024.
🏗
Vector Store: pgvector extension on PostgreSQL (RDS). Column: kb_chunks.embedding vector(1024), metric: cosine similarity.
📝
BM25 index: kb_chunks.bm25_text tsvector — hybrid retrieval (dense vector + sparse BM25) at query time.
🔄
Resumable: kb_embed skips rows with embed_status=EMBEDDED. Retries FAILED_RETRYABLE when retry_failed=True.
🛑
Credential expiry: Returns exit_code=2 on Bedrock credential expiry — safe to resume after re-auth.

Knowledge Graph Construction & Rendering

From document extraction → graph.json → Postgres → NetworkX → D3 visualization

✓
The graph uses no Neo4j in production. Nodes and edges are stored in Postgres (kb_nodes / kb_edges) and loaded into a NetworkX DiGraph in-memory per gear (LRU-cached up to 20 gears). The UI renders via D3 v7 with two modes: swimlane (Layers) and force-simulation (Explore).

Chat / RAG Query Pipeline

From user question → hybrid retrieval (vector + BM25 + graph) → streamed LLM answer with citations

ℹ
Chat uses three retrieval signals in parallel: dense vector search (pgvector cosine), sparse BM25 (tsvector), and graph neighbourhood context (NetworkX). Results are ranked, fed to a LangGraph ReAct agent, which calls AWS Bedrock Claude to synthesize the grounded answer. The Angular UI receives it as Server-Sent Events (SSE) and renders tokens word-by-word.

🔄 SSE Event Types & UI Rendering

1
status — Pipeline stage updates: understand → retrieve → rank → synthesize → ground. Angular renders as a live collapsible step list.
2
token — Partial text from Claude. Angular appends to message bubble + calls ChangeDetectorRef.detectChanges() immediately (bypasses zone batching).
3
retract — Sent if Claude backtracks on a partial statement. UI removes the retracted text.
4
abstain — Sent when no KB coverage found. Angular shows "not covered by the corpus" UI state instead of hallucinated answer.
5
done — Final event with {citations, answered, session_id}. Angular renders KB card ID chips + source loci as citation footnotes.
6
cancelled / error — User calls DELETE /fe/query/stop/{request_id} or server error. Angular shows error state gracefully.

☁️ Shared Infrastructure & Key Design Decisions

🐘
PostgreSQL + pgvector (RDS) is the single source of truth for all KB data at runtime — 7 tables: kb_nodes, kb_edges, kb_cards, kb_chunks, kb_sources, kb_evidence, kb_versions. Schema isolated per gear (search_path).
☁️
AWS Bedrock is used for two things only: (1) Titan Text Embeddings v2 for chunk indexing (MCP) and query embedding (API). (2) Claude via ChatBedrockConverse for LLM synthesis at query time. Model IDs never hardcoded — resolved from MODEL_REGISTRY_JSON.
🔐
HashiCorp Vault holds all secrets — Postgres passwords, Bedrock keys, S3 role ARNs. Never in config files or environment variables directly. Vault app codes are per-gear (4 tenants: Japan Auto, Claims, Scup, UW Credit Risk).
🔗
NetworkX (not Neo4j) for production graph. Neo4j config exists in registry but is deferred to v2. NetworkX DiGraph built on demand from Postgres, LRU-cached up to 20 gears. All graph queries are in-memory traversals.
🤖
Cite-or-Abstain rule enforced at two layers: Plugin's re_anchor.py gate (G9v) rejects FABRICATED evidence at build time. API's chat endpoint abstains with "not covered by the corpus" if no KB coverage found at query time.
📦
Multi-tenant via org/gear registry — 4 tenants share one RDS cluster but are isolated by Postgres schema (search_path). S3 buckets and prefixes are per-gear. MCP Tools registry.json maps org_id + gear_id to all config.
